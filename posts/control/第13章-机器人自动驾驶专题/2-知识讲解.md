## 一、机器人控制全景：你站在哪一层？

一个自主机器人（无人车、无人机、机械臂）的控制栈，从底到顶：

```
┌─────────────────────────────────────────────┐
│ 顶层：任务规划（去哪、干什么）                │
├─────────────────────────────────────────────┤
│ 决策：行为/路径规划（怎么走、走哪条线）        │
├─────────────────────────────────────────────┤
│ 路径跟踪（本章重点）：贴着规划线走             │
├─────────────────────────────────────────────┤
│ 状态估计（本章重点）：我在哪、我多快（卡尔曼）  │
├─────────────────────────────────────────────┤
│ 底层：电机/舵机执行（第12章数字PID就是干这个） │
└─────────────────────────────────────────────┘
```

> **第8/11/12章做的是最底层三格**；本章补上"路径跟踪 + 状态估计"两格，你就拥有了一个"能自主动起来"的最小闭环。第14章的强化学习/MPC 是在更高层做"决策"。

## 二、两种轮式车：差速车与阿克曼车

### 为什么？

控制一辆车，先回答："它的运动学是什么？"——这是所有上层算法的地基。

### 怎么做？是什么？

|      | 差速车                    | 阿克曼车（汽车）                   |
| ---- | ---------------------- | -------------------------- |
| 控制量  | 线速度 $v$ + 角速度 $\omega$ | 速度 $v$ + 前轮转角 $\delta$     |
| 运动方程 | $\dot x=v\cos\theta$ 等 | $\dot\theta=v\tan\delta/L$ |
| 转弯半径 | $R=v/\omega$（可原地转）     | $R=L/\tan\delta$（有下限）      |
| 生活例子 | 扫地机、仓储机器人、电动轮椅         | 汽车、自动驾驶                    |

![差速与阿克曼运动学](./figures/01_差速与阿克曼运动学.png)

*图 13-1 同样走圆弧：差速车靠 ω，阿克曼车靠 δ。控制量不同，但"输入→轨迹"的关系一目了然。*

> **生活类比**：差速车像"原地打转的舞者"（两个轮子速度差决定转多快）；阿克曼车像"开汽车"（只有前轮能转，还得往前开才能转）。自动驾驶当然研究后者，但**差速车公式更简单、调试更方便**，所以学习顺序是"先差速、后阿克曼"。

---

> **为什么车不能横着走？（非完整约束）** 差速车有 3 个状态 $(x,y,\theta)$ 却只有 2 个输入，更关键的是它被一条"滚动无侧滑"约束锁死：速度方向永远等于车头朝向，**无法直接横移**。数学上这是条"不可积的微分约束"（nonholonomic），后果是——你不能用一个简单的"看状态给输出"的静态控制器把车停到任意姿态（Brockett 定理）。所以移动机器人的控制器都是"先跟路径、再收敛"的几何式设计（纯跟踪/Stanley），而机械臂却能直接上 LQR 全状态镇定。**这条约束是"移动机器人"和"机械臂"两个世界的分界线，也是你理解"为什么自动驾驶控制这么设计"的钥匙。**

## 三、路径跟踪：贴线走的两大流派

### 为什么？

规划层给你一条线（车道中心线、巡航路线），但车有惯性、有误差，**怎么保证贴着线走？** 这就是横向控制。

### 怎么做？是什么？

**纯跟踪（Pure Pursuit）**——"看着前面 Ld 米处的一个点，沿着指向它的圆弧走"：

```
① 在路径上找车前 Ld 处的点 P
② 算车头与 P 连线的夹角 α
③ 差速车：ω = 2v·sinα / Ld   （阿克曼：δ = atan(2L·sinα / Ld)）
```

![纯跟踪路径跟踪](./figures/02_纯跟踪路径跟踪.png)

*图 13-2 红色点为前视点。车不看整条路，只看"前方 Ld 处的那个点"，然后转个合适的弯。前视点画得密的地方，就是车走得稳的地方。*

**Stanley**——"盯住横向误差 e，把车头掰回路径切线方向"：

$$
\delta = \psi + \arctan\frac{k\,e}{v}
$$

![纯跟踪与Stanley对比](./figures/03_纯跟踪与Stanley对比.png)

*图 13-3 从 3m 横向误差起步，两种算法都收敛到 0，但收敛的"性格"不同：Stanley 前期更急、更直；纯跟踪跟前视距离 Ld 的选择强相关。*

> **选型直觉**：路况简单（高速、缓弯）用 Stanley，收敛快且稳；路况复杂（绕桩、越野）用纯跟踪，因为它天然平滑、不冲撞。**两家都是"两行公式撑起一个自动驾驶横向控制器"的典范。**

---

### 业界真实做法：从两行公式到量产

- **Apollo（百度）**：横向控制标准方案是 **MPC**——把纯跟踪/Stanley 的"几何直觉"升级成"带约束的滚动优化"，把方向盘转角限幅、转向速率限幅、路径曲率都写进约束（第 14 章会系统讲 MPC）。纯跟踪/Stanley 在 Apollo 里作为 MPC 的**初始解和降级备选方案**；
- **Tesla / 百度量产车**：工程上大量使用 **Stanley 的变体**（横向误差 + 航向误差加权），因为它只需"横向误差 $e$ + 航向误差 $\psi$"两个量，不依赖前视点搜索，实时性极好；
- **学术/比赛（FSD、机器人竞赛）**：纯跟踪因**实现简单、参数少（就一个 $L_d$）**，仍是入门首选——很多参赛车队的第一个跑起来的控制器就是纯跟踪。

> 记住这条脉络：**纯跟踪（几何、简单）→ Stanley（几何、更稳）→ MPC（优化、带约束）**，就是自动驾驶横向控制从"玩具"到"量产"的完整进化路线。你现在学的两行公式，正是这条路线的最底下一层——地基打牢，后面的 MPC 才学得懂。

## 四、纵向控制：油门与刹车

- **定速巡航** = 速度环 PI：$u = K_p(v_{ref}-v) + K_i\int(v_{ref}-v)dt$；
- **ACC 自适应巡航** = 把目标换成"安全跟车距离 $d_{ref}=d_0+\tau v$"，误差里还含相对速度。

> 一句话：纵向控制**没有新理论**，是第8章 PI 的"工程化"——难点全在调参、限幅、抗积分饱和（第12章）这些"脏活"上。这恰恰说明：**工程价值 = 经典控制 × 工程细节**。

### 数字实现的采样频率怎么选？

控制器写进单片机/工控机就是数字控制，采样周期不能随便定。第12章的结论落到工程上有一条经验判据：**控制频率应达到被控系统闭环带宽的 5~20 倍以上**。以定速巡航为例，速度环带宽通常只有 0.1~1 Hz，取采样周期 $T_s=0.05$s 即 20 Hz，是带宽的 20~200 倍——**绰绰有余**，此时采样不是瓶颈，真正的瓶颈在油门执行器响应与通信延迟。反过来，若采样频率掉到与带宽同量级，零阶保持器的相位滞后会让原本稳定的回路振荡甚至失稳。先估带宽、再定采样率，是数字控制设计的标准顺序。（对应练习题8）

## 五、无人机串级 PID：两环套娃

### 为什么？

单环 PID 直接控角度，无人机一有扰动就晃；串级 PID（外环角度 + 内环角速度）是**行业标配**。

### 怎么做？是什么？

```
              ┌─────────── 外环（慢）───────────┐
θ_cmd ──→ [+][Kp外] ──→ ω_cmd ──→ [+][PI内] ──→ τ ──→ 姿态动力学
               └── θ(测) ←──────────────────────┘
                          └── ω(测) ←──────────────┘
```

![无人机串级PID](./figures/04_无人机串级PID.png)

*图 13-4 外环角度环给出"角速度指令"，内环角速度环追指令出力矩。3s 处加扰动力矩，角度被很快拉回——内环先把扰动"吸收"掉，外环几乎感觉不到。*

### 调参口诀（面试常问）

1. **先内后外**：内环（角速度）调稳调快，再碰外环（角度）；
2. **外慢内快**：外环带宽约为内环的 1/3~1/5；
3. **串级的意义**：内环像"助手"，把所有扰动在还来得及反应时处理掉，外环就能专心"摆姿势"。

> **生活类比**：外环是"教练"（看动作是否标准，下指令"转快点"），内环是"身体"（真出力转）。教练只下指令，不亲自转——所以哪怕身体被风吹歪（扰动），教练的指令依然准确。

## 六、卡尔曼滤波：具身智能的"眼睛"

### 为什么？

机器人想知道"我在哪"，但：
- 位置能测，速度测不到（或测不准）；
- 传感器有噪声（GPS 抖、雷达有杂波）。

**把"不完美的测量" + "系统的运动模型"融合，得到"最可能的真实状态"**——这就是卡尔曼滤波。

### 怎么做？是什么？

两大步循环：
1. **预测**：用运动模型 $\hat x = F\hat x$ 往前推一步（顺带把不确定性 $P$ 也变大一点）；
2. **更新**：来了测量 $z$，按"谁可信就多信谁"分配权重 $K$，把估计拉向测量。

$$
K = \frac{\text{模型不确定性}}{\text{模型不确定性}+\text{测量噪声}}
$$

![卡尔曼滤波](./figures/05_卡尔曼滤波.png)

*图 13-5 红色散点是带噪声的位置测量，黑色是真实轨迹（机器人自己也不知道），蓝色是卡尔曼滤波输出——几乎贴着真实轨迹，而且"速度"这种测不到的物理量也被估出来了（下子图）。*

> **工程意义**：自动驾驶"多传感器融合"、无人机 VIO、机械臂末端估计、马斯克的 FSD、卫星导航——全是卡尔曼滤波或其变体（EKF/UKF/粒子滤波）。**它是"控制 + 感知"的桥，也是第14章强化学习里"观测"的现实版。**

---

### 为什么卡尔曼是"最优"而不是"好用"？

卡尔曼滤波不是"一个效果不错的加权平均"，它有**严格的最优性证明**（公式推导 §5.4）：在"线性 + 高斯 + 不相关"三个假设下，那个增益 $K$ 是**让后验误差协方差最小的唯一解（MMSE）**。换句话说，只要假设成立，**没有任何其他线性滤波器能比 KF 的均方误差更小**——这是数学保证，不是经验。

这也是它 60 年不换的原因：IMU/GPS 组合导航、无人机飞控、自动驾驶多传感器融合，全在用它。一旦假设被打破（非线性、非高斯），才有 EKF/UKF/粒子滤波——**它们都是"在 KF 最优性的地基上"搭起来的近似**。理解了"KF 凭什么最优"，你就理解了整个估计学科为什么长成现在这样。

## 七、倒立摆大项目：把全课串成一条线

### 项目定位

> 倒立摆 = 控制界的 hello world。它同时具备机器人最难的四件事：**欠驱动、开环不稳定、状态不完全可测、执行器饱和**。你能在仿真里把它稳住，就说明前面11章不是白学的。

### 线性化的适用范围：LQR 不是万能的

第11章的 LQR 建立在 $\sin\theta\approx\theta$ 的线性化上，它只在**平衡点的小邻域**内成立。初始倾角越大，线性化误差越大：$\theta=0.6$ rad 时 $\sin0.6=0.565$，相对误差约 $\dfrac{|0.565-0.6|}{0.6}\approx6\%$，LQR 还能勉强稳住；超过 0.8 rad 后先冲出线性区、执行器饱和，最终失稳。练习里把初始倾角从 0.2 rad 加到 0.6 rad，正是验证"线性控制器的适用范围"边界——这在工程上叫"线性化有效的吸引域"。若想在大角度下仍能工作，就需要非线性手段（增益调度、MPC、RL），这也是第14章的动机之一。（对应练习题15）

### 项目路线（五站）

```
第1站 建模    物理定律 + 线性化 → 4状态方程（第3、11章）
第2站 分析    特征值判稳、根轨迹、Bode → 确认"这玩意天生不稳"（第5~7章）
第3站 设计    PID / 超前校正 / LQR 三选一，仿真稳住（第8、11章）

第5站 跑通    PyBullet 里从"数学上稳住"到"物理仿真里稳住"（本章）
```

## 八、PyBullet：从纸面到"物理世界"

**PyBullet** 是一个免费物理仿真引擎（Python 一行命令安装），有真实的碰撞、摩擦、重力、电机模型。它的意义：**数学仿真里稳住的，物理仿真里不一定稳**（有延迟、有噪声、有模型误差）——跨越这道坎，才是真本事。

```python
import pybullet as p
p.connect(p.GUI)                    # 打开 3D 窗口
p.loadURDF("inverted_pendulum.urdf")  # 加载倒立摆/小车模型
# 循环：读传感器 → 算 LQR → 给电机力矩 → p.stepSimulation()
```

> **学习建议**：先学会"拿 PyBullet 当仿真器"（跑起来、读状态、发指令），不要一上来就追求逼真模型。跑通了再说"加摩擦、加噪声、加延迟"。
