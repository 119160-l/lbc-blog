# 第13章 机器人/自动驾驶专题——项目实战

> **本文件的定位**：`4-仿真与绘图.md` 里的 5 张图是"玩具级仿真"——公式对、现象清楚，但没碰过真实世界的脏（传感器噪声、执行器死区、坐标系对齐、几百个文件的工程）。本章的 4 个项目实战，全部来自**真实论文与真实开源项目**，按"先复现论文 → 再进工业框架 → 最后看前沿"的顺序排列。
>
> **怎么用**：每个项目给一条"青铜 → 黄金 → 王者"的路线。青铜是"跑通别人的代码"，黄金是"改参数、改结构做对比实验"，王者是"把学到的东西接到你自己的系统上"。**不求全部做完，每章至少完整做完一个青铜 + 一个黄金**。
>
> **环境准备**：项目 A 只需 `pip install numpy matplotlib`；项目 B 需要 Ubuntu 22.04 + ROS 2 Humble（虚拟机或双系统均可，建议先只装 ROS 2 桌面版）；项目 C/D 按各项目 README 走。

## 项目 A：经典论文复现——Pure Pursuit 与 Stanley 的"原始论文版"

### 为什么要做

你在 `4-仿真与绘图.md` 图2/图3 已经手写过纯跟踪和 Stanley。但工业界的实现和你手写的有一个本质区别：**真实路径不是函数 `path_fn(t)`，而是带弧长的离散路点序列，前视距离还要随速度自适应**。做完这个项目，你就理解了"教科书两行公式"到"能上车的控制器"之间差了什么。

### 读哪两篇原始论文

| 算法 | 原始论文 | 年份 | 一句话核心 |
|---|---|---|---|
| Pure Pursuit | R. C. Coulter, *Implementation of the Pure Pursuit Path Tracking Algorithm*, CMU-RI-TR-92-01 | 1992 | "看着前方 Ld 处的点，沿圆弧开过去"；首次给出前视距离与速度挂钩的工程规则 |
| Stanley | G. Hoffmann, C. Tomlin, M. Montemerlo, S. Thrun, *Autonomous Automobile Trajectory Tracking for Off-Road Driving*, IROS | 2007 | 斯坦福"Stanley"夺冠 DARPA 城市挑战赛的横向控制器：$\delta=\psi+\arctan(ke/v)$，用 Lyapunov 证明了渐近收敛 |

> 两篇论文都能在 arXiv/CMU 技术报告库免费拿到。**先读 Coulter 1992 的第 3 节（几何推导）和 Hoffmann 2007 的收敛性证明**——你会发现公式和本章图2/图3 完全一样，但论文里多出来的全是"工程注记"（奇异处理、限幅、速度自适应），这些注记才是论文真正的价值。

### 用哪个开源项目复现

**`PythonRobotics`**（Atsushi Sakai 等，GitHub 上 star 数最高的机器人算法教学库之一，仓库：`https://github.com/AtsushiSakai/PythonRobotics`，路径：`PathTracking/pure_pursuit/` 与 `PathTracking/stanley_controller/`）。它的优点是：纯 Python + matplotlib、每个算法一个单文件、代码与论文公式一一对应，注释里直接标了论文出处。

备选：`larics/pure_pursuit`（`https://github.com/larics/pure_pursuit`，ROS C++ 版，引用 Coulter 1992，适合以后接 ROS 时再用）。

### 实战路线（青铜 → 王者）

**青铜（1~2 天）：跑通 + 对照论文**
1. `git clone https://github.com/AtsushiSakai/PythonRobotics.git`，`pip install numpy scipy matplotlib`；
2. 运行 `python PathTracking/pure_pursuit/pure_pursuit.py` 与 `stanley_controller.py`，看动画输出；
3. 逐行对照 Coulter 1992 的公式，在代码里找到三件事：前视点是怎么在**离散路点序列**里插值出来的（不是你手写版的 `path_fn`）、`alpha` 的符号约定、转向限幅在哪。

**黄金（2~3 天）：速度自适应前视距离**
1. 把前视距离从固定值改成 $L_d = k\,v + L_{d,\min}$（Coulter 原文的工程做法，$k$ 约 0.5~1.0 s），重跑：低速绕弯和高速直道的表现分别怎么变；
2. 给 Stanley 加一个软饱和项 $\arctan$ 之外再叠速度相关阻尼（Hoffmann 论文里的 $\arctan(k e/(k_s+v))$ 形式），对比收敛曲线；
3. **输出物**：一张"固定 Ld vs 自适应 Ld"的横向误差对比图（复用第13章绘图.py 的画图风格）。

**王者（1~2 周）：闭环接上你的第13章代码**
把你手写的差速车运动学 + 串级 PID 与 PythonRobotics 的阿克曼 Pure Pursuit 拼起来：路径跟踪给出 $\delta$ 指令，串级 PID 把它当"角度环"执行，观察执行器延迟（给 $\delta$ 加 50ms 一阶滞后）对跟踪误差的影响——**这就是真实车辆控制里"算法-执行器耦合"的最小实验**。

### 验收标准

- 能指出 PythonRobotics 里前视点插值与 Coulter 原文的对应行号；
- 自适应 $L_d$ 实验曲线能解释"为什么高速要看得更远"（呼应本章图2思考题2）。

## 项目 B：工业级开源栈——Autoware 的横向控制器（Pure Pursuit / Stanley / MPC 三选一）

### 为什么要做

Apollo、Autoware 是自动驾驶工业级开源栈的代表。**Autoware Universe 的 control 模块同时提供了 pure pursuit、Stanley 变体和 MPC 三种横向控制器**（`control/lateral_controllers` 目录下），是"两行公式 → 量产代码"进化的活标本——你会看到工业代码里多出来的东西：低通滤波、斜率限制、速度调度、看门狗。

仓库：`https://github.com/autowarefoundation/autoware.universe`（Autoware Foundation / Tier IV 维护，ROS 2 原生）。

### 实战路线

**青铜（半天~1 天，不跑仿真也能做）：读代码**
1. 不用装整套 Autoware。直接克隆仓库，只读 `control/lateral_controllers/mpc_lateral_control/`（或 `pure_pursuit`）；
2. 找到三件事并在笔记里写下来：**① MPC 的预测模型是几阶的、离散周期是多少（看 `mpc_core.cpp` 里 QP 的构造）；② 前视/权重参数从哪个 yaml 文件读入；③ 控制器里对"急转弯 + 低速"做了什么保护**。
3. **只读代码不运行，也是合格的青铜**——工业代码的阅读能力本身就是硬技能。

**黄金（需要 Ubuntu 22.04 + ROS 2 Humble，约 1 天编译 + 半天调参）**
1. 按 Autoware 官方文档的 "Source Installation" 装好（建议先只装 `autoware_launch` + `autoware_universe` 的 control 子集）；
2. 运行规划仿真：
   ```bash
   ros2 launch autoware_launch planning_simulator.launch.xml \
     map_path:=<下载好的示例地图> \
     vehicle_model:=sample_vehicle sensor_model:=sample_sensor_kit
   ```
   在 RViz2 里用 "2D Goal Pose" 给车一个目标，车会自己开过去；
3. 改 `mpc_lateral_control` 的参数文件：**把预测时域缩短一半、把横向误差权重调小 10 倍**，重编译重跑，在 RViz 里观察轨迹"切弯"程度——亲手验证第14章"MPC 三要素"的说法。

**王者：横向控制器切换实验**
把 lateral controller 从 MPC 换成 pure pursuit（改 launch 参数），同一条路线各跑一遍，用 `ros2 bag record` 录下横向误差，离线画对比图——**这就是一份可以写进简历/课程报告的小型评测实验**。

### 验收标准

- 能画出 Autoware control 模块的数据流：planning 输出的轨迹 → 重采样 → MPC/pure pursuit → 方向盘指令，并标出每一步对应的源文件；
- 能解释 MPC 版里 QP 的决策变量是什么（转向角增量序列）。

## 项目 C：真实飞控源码——PX4 EKF2 与串级 PID

### 为什么要做

本章图4 的串级 PID 和图5 的卡尔曼滤波，在真实世界有个"标准答案"：**PX4 飞控**（开源飞控事实标准之一，大疆之前的学术与工业无人机大量基于它；仓库 `https://github.com/PX4/PX4-Autopilot`，MIT 协议）。它的两个模块值得逐行读：

| 模块 | 位置 | 对应本章知识 |
|---|---|---|
| `ekf2` 状态估计 | `src/modules/ekf2/` | 图5 卡尔曼滤波的 24 维工业版：四元数姿态 + 速度 + 位置 + IMU 零偏 + 风速，全部一个 EKF 联合估计 |
| 串级 PID 姿态控制 | `src/modules/mc_att_control/`（外环姿态）+ `mc_rate_control/`（内环角速率） | 图4 串级 PID 的 C++ 量产版，含抗积分饱和（back-calculation）、低通滤波、输出限幅 |

配套阅读：PX4 开发者文档里的 *EKF2* 推导页（docs.px4.io → "State Estimation → EKF2"），把 24 维状态、预测/更新方程写得和课本一样清楚。

### 实战路线

**青铜（1 天）：读串级 PID，对照图4**
1. 打开 `mc_att_control`，找到"姿态误差 → 角速度指令"的那行（外环输出限幅在哪）；
2. 打开 `mc_rate_control`，找到角速率 PID 的积分项和 **back-calculation 抗饱和**代码——回看第12章的"积分饱和坑"，在工业代码里找到它的解药。

**黄金（2~3 天）：自己写一个"迷你 EKF2"**
1. 用 numpy 复现一个 7 维 EKF：四元数(4) + 陀螺零偏(3)，量测是加速度计+磁力计（这就是"姿态解算"的最小完整问题）；
2. 注入陀螺零偏（如 0.5°/s）和加速度计噪声，验证 EKF 能把零偏估出来（对应本章图5 的"测不到的量也能估"）；
3. **输出物**：一张"真值姿态 vs EKF 估计 vs 纯陀螺积分"的三曲线对比图。

**王者（选做，需要 Linux + 约 20GB 磁盘）：跑 PX4 的 SITL**
装 PX4 的 Simulation 工具链（`make px4_sitl gazebo-classic`），在纯仿真里让四旋翼起飞悬停，然后用 `mavlink_shell` 实时打印姿态估计，人为给仿真加一阵风（Gazebo 里对模型施加外力），观察 EKF2 输出与控制器的反应——**第13章"扰动来了怎么办"在这里有了真机级的答案**。

### 验收标准

- 能说出 PX4 串级 PID 里"外环输出限幅"和"内环抗饱和"分别防的是什么（提示：外环防角速度指令过大 = 本章图4思考题6；内环防积分堆积 = 第12章）；
- 迷你 EKF2 的零偏估计曲线收敛到注入真值的 ±20% 以内。

## 项目 D（前沿拓展，选做）：端到端自动驾驶——看懂"学习式横向控制"

### 为什么要看

本章的 Pure Pursuit/Stanley 是"人写规则"，而近三年的前沿是**端到端**：从传感器图像直接学出轨迹/控制。你不需要会训这种模型（那是深度学习课的事），但**要能看懂它的评测方式和失败模式**——这是算法工程师面试的常见话题。

| 项目                   | 出处                                        | 一句话                                                    | 仓库                                              |
| -------------------- | ----------------------------------------- | ------------------------------------------------------ | ----------------------------------------------- |
| UniAD                | CVPR 2023 最佳论文（Yihan Hu 等 / OpenDriveLab） | 感知-预测-规划统一成一张网络，"规划导向"的联合优化                            | `https://github.com/OpenDriveLab/UniAD`         |
| VAD                  | ICCV 2023（Bo Jiang 等 / HUST & 地平线）        | 向量化场景表示替代栅格化，推理速度提升数倍                                  | `https://github.com/hustvl/VAD`                 |
| Learning by Cheating | CoRL 2019（Dian Chen 等）                    | 模仿学习经典：先用"作弊信息"（地图/他车位置）训老师，再蒸馏成只看图像的学生——直观演示"协变量偏移"问题 | `https://github.com/dotchen/LearningByCheating` |

### 实战路线（轻量版，不需要 GPU 也能完成青铜）

1. **青铜**：只看论文 + 演示视频。UniAD 论文第 3 节画出了整张网络的结构图，把它和本章图5 的"全景架构图"对照——**端到端 = 把图里"感知→估计→规划"三层压成一个可微分的大模块**；
2. **黄金**：下载 UniAD 的 nuScenes-mini 演示包（按 README），跑通官方可视化 demo（无需训练），看它的规划轨迹可视化，思考：如果这个网络没见过"施工锥桶改道"，它会怎样？（答案方向：训练分布外 → 这正是传统 MPC/几何方法仍保留为"兜底"的原因）；
3. **王者（选做）**：在 CARLA 仿真器里跑 Learning by Cheating 的预训练权重，观察学生在没见过的天气下掉分——**把"泛化失败"和 Stanley 的 Lyapunov 稳定性证明放在一起看，你就理解了为什么量产车仍然要"学习做决策、经典控制兜底"**。
