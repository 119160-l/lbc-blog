# 第15章 强化学习进阶——项目实战

> **本文件的定位**：本章的手写 DQN/PPO 已经让你看懂了算法的"五脏六腑"。但工业界的 RL 代码有三个你没碰过的东西：**卷积视觉输入（Atari 级观测）、GPU 并行采样、真机部署管线**。本文件的 3 个项目正好补上这三块：CleanRL 单文件复现（论文↔代码逐行对应）、NVIDIA Isaac Lab 四足训练（域随机化 + sim-to-real 全流程）、以及 sim-to-real 的前沿研究方向。
>
> **硬件要求**：项目 A 普通笔记本可做（Atari 训练慢，可先跑 CartPole 版）；项目 B 需要 NVIDIA 显卡（建议 RTX 3060 以上，越新越好）；没有 GPU 就把项目 B 降级为"读配置 + 看官方博客"。

---

## 项目 A：经典复现——CleanRL：一行行对照你手写的 DQN/PPO

### 为什么要做

**CleanRL**（Huang 等，JMLR 2022；仓库 `https://github.com/vwxyzjn/cleanrl`）是强化学习界的"教科书代码库"：每个算法一个单文件，没有框架封装，`dqn_atari.py` 一个文件就是完整 DQN，`ppo_continuous_action.py` 一个文件就是完整 PPO。**它和你的手写版之间的差距，就是"教学代码"到"可复现论文结果"的距离**——这个距离里的每一行（帧堆叠、优势归一化、学习率调度、随机种子管理）都是工程经验。

配套对照物：**PPO-PyTorch**（Nikhil Barhate，`https://github.com/nikhilbarhate99/PPO-PyTorch`），约 300 行的极简 PPO，clip 目标和 GAE 的实现和本章手写版几乎同构，是最适合"第一遍通读"的 PyTorch PPO。

### 实战路线

**青铜（1 天）：通读 PPO-PyTorch，逐行对照手写版**
1. `git clone https://github.com/nikhilbarhate99/PPO-PyTorch.git`，装好依赖；
2. 打开 `PPO.py`，找到三处并做笔记：**① clip 目标 `torch.min(surr1, surr2)` 对应本章图4 的哪几行；② GAE 的 `lambda` 在哪算；③ 策略熵奖励为什么加**（本章手写版没加熵项——想想为什么工业版都要加）；
3. 跑 `python train.py`（默认任务换成 `CartPole-v1` 或 `LunarLanderContinuous-v2` 更快），看奖励曲线。

**黄金（2~3 天）：CleanRL 的 clip 与超参实验**
1. 跑 CleanRL 的 `cleanrl/ppo_continuous_action.py --env-id HalfCheetah-v4`（MuJoCo 连续控制，本章倒立摆的"工业表亲"）；
2. **把 `clip-coef` 从 0.2 改成 0.05 和 0.4 各重跑一次**，对比训练曲线的稳定性——亲手复现"clip 半径 = 步子约束"（本章图4思考题4）；
3. **输出物**：三曲线对比图 + 一张表（clip=0.05/0.2/0.4 的收敛速度与最终回报）。

**王者：把 Atari DQN 跑起来（需要耐心 + 几小时训练）**
1. `python cleanrl/dqn_atari.py --env-id BreakoutNoFrameskip-v4`；
2. 读代码里的**帧堆叠**（4 帧灰度图叠成输入）——这是"状态怎么表示"的又一次实战：单帧图像没有速度信息，堆叠 4 帧才够 DQN 用（回想本章图2"状态表示决定一切"）；
3. 训练几小时看到得分明显上升即可停止，截图留档。

### 验收标准

- 能在 CleanRL PPO 文件里指出 GAE、clip、熵奖励各自的代码位置；
- clip 扫描实验有图有表，能解释 0.05 为什么"太保守"。

## 项目 B：工业级 sim-to-real——Isaac Lab 训练四足行走（宇树 Go2）

### 为什么要做

本章图5 画了"仿真→域随机化→部署真机"的管线，NVIDIA 把它做成了开箱即用的产品：**Isaac Lab**（仓库 `https://github.com/isaac-sim/IsaacLab`，前身 Isaac Gym + Orbit）。官方内置 `Isaac-Velocity-Flat-Unitree-Go2-v0` 任务——用 PPO 训练宇树 Go2 四足机器人跟踪速度指令，**这就是宇树/行业里"RL 步态"的最小完整版本**。NVIDIA 还发过官方博客《Closing the Sim-to-Real Gap: Training Spot Quadruped Locomotion with NVIDIA Isaac Lab》，用波士顿动力的 Spot 走通了同一条管线。

### 实战路线

**青铜（半天，无 GPU 也可）：读任务配置，理解 RL-MDP 的"工业写法"**
1. 克隆 Isaac Lab 仓库，打开四足速度跟踪任务的配置文件（`source/isaaclab_tasks/.../manager_based/locomotion/velocity/config/go2/` 下的 cfg 文件）；
2. 回答四个问题（写在笔记里）：**观测空间有哪些量**（基座角速度、重力投影、关节位置/速度、上一时刻动作、指令速度）？**奖励由哪几项加权**（线速度跟踪、角速度跟踪、动作平滑惩罚、足部滑移惩罚）？**动作空间是什么**（12 个关节的目标位置增量）？**终止条件是什么**（基座翻倒、超时）；
3. 对照本章知识讲解的术语表——**这就是"状态/动作/奖励"在真实产品里的样子**。

**黄金（有 NVIDIA GPU，1~2 天）：训练 + 域随机化实验**
1. 按官方文档装好 Isaac Sim + Isaac Lab，运行训练：
   ```bash
   ./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/train.py \
     --task Isaac-Velocity-Flat-Unitree-Go2-v0
   ```
   （首次训练几千个并行环境，RTX 3060 上约几十分钟到一两小时收敛）；
2. 用 `play.py` 加载 checkpoint 看机器人行走；
3. **域随机化实验**：在环境配置的 `events` 项里找到质量/摩擦/电机增益的随机化参数，**把随机化范围全部设为 0 再训一次**，然后给仿真加一个外部推力扰动，对比两个策略的抗扰表现——**这就是"域随机化 = 给策略打疫苗"（本章六节）的直接证据**。

**王者（选做）：走一遍部署管线**
1. 用 `play.py --export` 把策略导出为 `policy.onnx`；
2. 写一个最小推理脚本（ONNX Runtime，几十行）：输入"观测向量"，输出 12 维动作——**不接真机，也要把"策略 → 可部署模型文件 → 推理代码"这条链亲手走一遍**。真机部署（Go2 板载电脑）按宇树官方 SDK 文档走，风险自负、建议有实机指导再做。

### 验收标准

- 能完整说出 Go2 任务的观测/动作/奖励三件套；
- （黄金）"有随机化 vs 无随机化"的抗扰对比结论；
- （王者）一个能加载 onnx 并输出动作的推理脚本。

## 项目 C（前沿/科研向）：sim-to-real 的三个研究方向

### 为什么要看

本章六节给了 sim-to-real 三大对策（域随机化、课程学习、分层架构）。近两年的研究在回答同一个问题的更深处：**"仿真参数不准"能不能不靠撒网式随机化，而是主动辨识出来？** 以及 **"策略的鲁棒性上限能不能用对抗训练顶上去？"** 三个方向各给一个入口：

| 方向 | 代表工作 | 一句话 | 入口 |
|---|---|---|---|
| 系统辨识辅助 RL | ASID: Active Exploration for System Identification（Memmel 等，华盛顿大学，2024；arXiv 检索 "ASID active exploration system identification"） | 让机器人在真机上"主动做几个辨识动作"，用少量数据反推仿真器的物理参数（质量/摩擦/阻尼），再训练 → 零样本迁移成功率大幅提升 | 读论文 + 项目主页找官方代码（以论文页为准） |
| 大规模并行 + 域随机化的工业范式 | NVIDIA Isaac Lab Spot 案例（官方博客）、legged_gym 生态 | "上千并行环境 + 大范围域随机化 + 教师-学生蒸馏"是当前四足 RL 的事实标准 | Isaac Lab 文档；ETH `legged_gym`（`https://github.com/leggedrobotics/legged_gym`） |
| 分层架构的量产形态 | 宇树/行业的"高层 RL + 底层 MPC/WBC" | RL 输出步态级指令，底层模型预测控制保证力矩不超限、不摔机——本章知识讲解五节"两条腿走路"的真实产品形态 | 宇树开发者文档中的运动控制接口 |

### 实战路线（轻量）

**青铜**：读 ETH 的 `legged_gym`（Laikago/Anymal 环境，Isaac Gym 实现）README 与 `legged_robot.py`，找到它的域随机化参数表——和项目 B 的 Go2 配置对照，**两代框架的"随机化清单"几乎重合，这就是行业的共识参数**；

**黄金**：给项目 B 的策略做一个"对抗测试脚本"：在 play 时每隔 1 秒随机施加一个方向、幅值随机的外力，统计"存活率 vs 推力幅值"曲线——**鲁棒性第一次变成了一条可报告的曲线**；

**王者（科研）**：复现 ASID 的思想的最小版本——在你自己的倒立摆/小车仿真里故意把参数设错 30%，然后设计一个"辨识激励动作"（比如几段不同频率的正弦推力），用采集的数据回归出真实参数，修正仿真后重训——**这是"模型不准"问题从"撒网随机"走向"主动辨识"的第一步**。

### 验收标准

- 能列出 legged_gym 域随机化清单里至少 6 个参数；
- （黄金）一条"存活率 vs 扰动幅值"曲线。
