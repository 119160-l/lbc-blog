# 第17章 状态估计与 SLAM——项目实战

> **本文件的定位**：本章手写版已经做出了 KF/EKF/UKF、占用栅格、位姿图优化甚至状态增广——数学上你已经"会写 SLAM"了。但真实的 SLAM 系统还有四个你没碰过的东西：**① 真实传感器数据（EuRoC 数据集）；② 几百个文件的系统级代码（ORB-SLAM3/LIO-SAM）；③ 标准评测流程（ATE/RPE + evo 工具）；④ 因子图库与学习型回环检测**。本文件 4 个项目逐一补齐。
>
> **环境提示**：项目 A/B 都需要 Ubuntu + ROS 1（SLAM 主流代码仍建在 ROS 1 上，虚拟机即可）；项目 C 纯 Python 可做，强烈建议先做它——它是你手写代码和工业框架之间的桥；项目 D 读论文为主。

## 项目 C（建议第一个做）：把手写位姿图优化"接到"真实数据集上

### 为什么要做

本章图4 的 64 节点矩形是你自己造的。**真实世界的位姿图数据有标准格式（`.g2o` 文件：VERTEX2/EDGE2 行），有公开数据集**——g2o 项目自带的示例数据（intel 实验室、sphere 球面、parking 车库，`https://github.com/RainerKuemmerle/g2o` 仓库 `data/` 目录，或搜索 "g2o dataset"）。用你手写的高斯-牛顿去解这些真实数据，就是从"玩具"到"系统"最短的一跳。

配套升级目标：**g2o**（Kümmerle 等，ICRA 2011，图优化事实标准之一）与 **GTSAM**（Georgia Tech，因子图现代化身，LIO-SAM 的后端就是它）。

### 实战路线

**青铜（1 天）：读 .g2o 格式，加载 intel 数据集**
1. 下载 `intel.g2o`（约 1700 节点 + 3500 条边，一个真实办公室的激光里程计 + 回环数据）；
2. 写 30 行解析器：`VERTEX2 id x y theta` → 你的节点数组；`EDGE2 id_i id_j x y theta i11 i12 i22 i13 i23 i33` → 边 + 信息矩阵（下三角 6 个数拼成 3×3）；
3. 画出"优化前"的轨迹——**你会看到真实漂移：整张地图错位、走廊弯曲成弧形**，和本章图4 的矩形缺口是同一种病，只是大了几个量级。

**黄金（1~2 天）：你的手写优化器跑真实数据**
1. 把本章图4 的 `optimize` 原封不动接上（改一下节点初始化策略：用里程计链做初值）；
2. 跑高斯-牛顿，记录 $\chi^2$ 收敛曲线与优化前后轨迹图——**本章图4 的"一个回环拧正整条链"会在 1700 节点上重演**；
3. **升级实验**：编译 g2o（或 `pip install` 相关工具），用 g2o 自带求解器跑同一份数据，对比两者的 $\chi^2$ 终值与轨迹——**验证你手写的和"工业标准"结果一致**（差异应来自迭代次数与初值，而非算法）。

**王者：LM（Levenberg-Marquardt）升级**
g2o 默认用 LM 而非纯高斯-牛顿（带阻尼项 $\lambda$，初值差时更稳）。给你的求解器加上 LM 阻尼，故意给 10% 的节点注入大初值误差，对比"GN vs LM"的鲁棒性——**这就是第16章阻尼最小二乘思想在图优化里的同款应用，数学是一个**。

### 验收标准

- 你的优化器在 intel.g2o 上 $\chi^2$ 下降 ≥2 个数量级，轨迹肉眼可见地"拧正"；
- 能解释 `.g2o` 文件里信息矩阵为什么只存 6 个数（对称）。

## 项目 A：经典论文复现——ORB-SLAM3 / VINS-Mono 跑 EuRoC 数据集

### 为什么要做

这是"视觉 SLAM 界的两篇必读论文 + 两个必跑系统"。跑通它们，你就同时见过了**滤波式后端（VINS-Mono 的滑动窗口）和图优化式后端（ORB-SLAM3 的位姿图 + BA）**——本章知识讲解第四节"两条破解路线"的活标本。

| 系统 | 论文 | 年份 | 仓库 |
|---|---|---|---|
| ORB-SLAM3 | Campos 等, *ORB-SLAM3: An Accurate Open-Source Library for Visual, Visual-Inertial and Multi-Map SLAM*, IEEE T-RO | 2021 | `https://github.com/UZ-SLAMLab/ORB_SLAM3` |
| VINS-Mono | Qin, Li, Shen, *VINS-Mono: A Robust and Versatile Monocular Visual-Inertial State Estimator*, IEEE T-RO | 2018 | `https://github.com/HKUST-Aerial-Robotics/VINS-Mono` |

数据集：**EuRoC MAV**（苏黎世联邦理工的无人机视觉惯性数据集，`https://projects.asl.ethz.ch/datasets/doku.php?id=kmavvisualinertialdatasets`，V1_01_easy 入门，MH_01_easy 带真值）。

### 实战路线

**青铜（1~2 天）：编译 ORB-SLAM3 并跑通一个 demo**
1. Ubuntu 20.04 + ROS Noetic，按 README 编译 Pangolin、OpenCV、Eigen、DBoW2、g2o（编译坑多，**每个报错都值得读懂**——SLAM 工程师的日常）；
2. 下载 EuRoC `V1_01_easy`，跑单目模式：
   ```bash
   ./Examples/Monocular/mono_euroc ./Vocabulary/ORBvoc.txt \
     ./Examples/Monocular/EuRoC.yaml <数据集路径>/mav0/cam0/data ./Examples/Monocular/EuRoC_TimeStamps/V101.txt
   ```
3. 看它一边建稀疏地图一边跟住轨迹——**找出界面上三个区域，分别对应本章图5 管线的哪一层**（特征跟踪=前端、地图点=建图、轨迹=估计输出）。

**黄金（1 天）：装 evo，学会 SLAM 的"标准体检"**
1. `pip install evo`（SLAM 轨迹评测事实标准工具）；
2. 把 ORB-SLAM3 输出的轨迹转成 TUM 格式，与 EuRoC 真值对齐，算两个指标：
   ```bash
   evo_ape tum groundtruth.txt trajectory.txt --align --plot
   evo_rpe tum groundtruth.txt trajectory.txt --delta 100
   ```
   **ATE（绝对轨迹误差）= 本章 RMSE 的全局版；RPE（相对位姿误差）= 局部漂移**——学会这两个词，所有 SLAM 论文的表格你都读得懂；
3. 对比 V1_01_easy 和 V1_03_difficult（快速运动 + 弱纹理）的 ATE——**感受"难度"在数据里的物理含义**（模糊、运动模糊、特征缺失）。

**王者（选做）：VINS-Mono 与 ORB-SLAM3 正面对决**
编译 VINS-Mono（依赖 Ceres Solver），同一 EuRoC 序列两边各跑一遍，用 evo 出同一张对比图：**视觉惯性（VINS）在快速运动段为什么明显更稳？**（答案：IMU 预积分补上了特征跟丢的空窗——本章知识讲解 7.2 节的"前端"分工，用数据验证。）

### 验收标准

- 一次成功编译 + 一次成功运行（过程里的报错笔记保留）；
- 一张带 ATE/RPE 数值的评测图，能解释 align（Sim(3) 对齐）为什么必须做。

## 项目 B：工业级激光惯性 SLAM——LIO-SAM

### 为什么要做

大疆系激光雷达建图、无人车高精地图的开源代表就是 **LIO-SAM**（Shan 等，IROS 2020，仓库 `https://github.com/TixiaoShan/LIO-SAM`）。它的代码结构是本章图5 管线的**逐文件对应版**，读完它你对"前端/后端/回环"的理解会从示意图变成源代码。

| 本章概念 | LIO-SAM 源文件 |
|---|---|
| 前端：逐帧处理 | `imageProjection.cpp`（点云去畸变）+ `featureExtraction.cpp`（角点/面点提取） |
| 前端：扫描匹配 | `mapOptimization.cpp` 里的激光里程计部分（点到线/点到面 ICP） |
| 后端：因子图 | `mapOptimization.cpp` 里的 GTSAM 部分：IMU 预积分因子 + 激光里程计因子 + GPS 因子 + 回环因子 |
| 回环检测 | 基于半径/时间的候选 + ICP 验证 |

### 实战路线

**青铜（1 天）：跑通官方 demo + 模块对号入座**
1. Ubuntu 20.04 + ROS Noetic，装 GTSAM、PCL、Eigen，`catkin_make` 编译；
2. 下载官方 rosbag（仓库 README 给了公园/步行数据包），`roslaunch lio_sam run.launch` + `rosbag play <包名>.bag --clock`；
3. RViz 里订阅 `/lio_sam/mapping/path`（轨迹）和 `/lio_sam/mapping/cloud_registered`（地图）——**看一张真实公园的三维点云地图被"走"出来**；
4. 对照上表，打开四个源文件，各找到一处核心代码（比如 `mapOptimization.cpp` 里 GTSAM `add` 因子的那几行）。

**黄金（1~2 天）：外参与噪声参数实验**
1. `config/params.yaml` 里找到 `extrinsicRot`/`extrinsicRPY`（IMU 与 LiDAR 的相对位姿外参）——**故意把 RPY 改错 5° 重跑**，观察地图"分层/重影"现象，体会"外参不准 = 两个传感器说的不是同一个坐标系"；
2. 调 `imuGravity` 与 IMU 噪声参数，观察垂直方向漂移的变化——**呼应本章图6 的教训：模型参数错，残差和轨迹一起烂**。

**王者（选做）：回环开关实验**
在参数里关掉回环检测（`loopClosureEnableFlag: false`），同一段数据重跑：**大场景下轨迹开始漂移、地图撕裂**——本章"没有回环就没有全局修正"的论断，在真实公园里眼见为实。

### 验收标准

- 能画出 LIO-SAM 的节点图（ROS topic 流向）：点云 → 去畸变 → 特征 → 匹配 → 因子图 → 发布；
- 外参改错实验有"改前 vs 改后"的地图对比截图。

## 项目 D（前沿，选做）：回环检测的新范式——大模型与神经地图

### 为什么要看

本章图4 默认"回环是给定的"。真实系统里回环检测本身是最容易错的一环（外观相似但地点不同的"感知混叠"）。近两年的两条前沿路线：

| 方向 | 代表 | 一句话 | 入口 |
|---|---|---|---|
| 基础模型做地点识别 | DINOv2-SALAD（Izquierdo & Civera，萨拉戈萨大学，CVPR 2024；Sinkhorn 最优传输聚合） | 用自监督预训练的 DINOv2 特征 + 最优传输聚合出全局描述子，跨季节/光照的"这是不是同一个地方"判断达到 SOTA | 仓库 `https://github.com/serizba/salad`（含预训练权重） |
| 神经场 + 位姿图 | Neural Graph Mapping（Bruns, Zhang, Jensfelt，KTH，WACV 2025，arXiv 2405.03633） | 把轻量神经场"锚定"在稀疏 SLAM 的位姿图上，稠密建图也能高效吃进回环约束——**"位姿图 + 回环"这个你手写的结构，正在成为神经 SLAM 的骨架** | 仓库 `https://github.com/KTH-RPL/neural_graph_mapping` |

### 实战路线（轻量）

**青铜**：读 SALAD 论文图 2 的流水线（DINOv2 提特征 → Sinkhorn 分配 → 局部聚合 → 全局描述子），回答：它替代的是 SLAM 管线里的哪一个模块？（答案：回环检测的"外观匹配"环节）；克隆仓库，加载预训练权重跑 README 的最小推理示例（给两张图算描述子距离），体会"同一地点不同时间拍的图距离近、不同地点距离远"；

**黄金**：读 Neural Graph Mapping 的架构图，找到"神经场锚定在位姿图节点上"的设计，对照本章图4 思考：**回环发生时，被修正的是位姿图节点，而神经场跟着节点一起"搬"——这就是"后端图优化"在神经表示时代的存活方式**；

**王者（科研向）**：把 SALAD 的描述子接到你自己的位姿图上——用任意带图像的数据集（如 TUM RGB-D），每帧算一个 SALAD 描述子，余弦相似度超过阈值就加一条回环边，跑你项目 C 的优化器——**"学习型前端 + 手写后端"的混合 SLAM 最小原型，这就是当下顶会论文的常见配方**。

### 验收标准

- 能解释 SALAD 相对传统词袋（BoW，ORB-SLAM 用的 DBoW2）的优势来源（预训练特征的泛化性）；
- （王者）至少一条由描述子相似度触发的回环边被优化器吃掉。
