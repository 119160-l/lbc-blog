## 图1 卡尔曼滤波：恒定速度目标跟踪

### 代码核心

状态 $(x,y,v_x,v_y)$，恒定速度模型（含随机加速度），GPS 级位置量测：

```python
A = [[1,0,dt,0],[0,1,0,dt],[0,0,1,0],[0,0,0,1]]     # 匀速运动
H = [[1,0,0,0],[0,1,0,0]]                             # 只量测位置
Q = diag([0.02,0.02,0.05,0.05])                       # 过程噪声（随机加速度）
R = diag([0.6,0.6])                                   # 量测噪声（GPS 级）
for k in range(120):
    x_pred = A @ x_est;  P_pred = A @ P @ A.T + Q     # ① 预测
    S = H @ P_pred @ H.T + R                          # ② 新息协方差
    K = P_pred @ H.T @ inv(S)                         # ③ 卡尔曼增益
    x_est = x_pred + K @ (meas[k] - H @ x_pred)       # ④ 更新
    P = (eye(4) - K @ H) @ P_pred
```

### 现象解释

- 位置量测散布 ±0.8m（红点），滤波轨迹（蓝线）平滑贴合真值（黑线），**位置 RMSE = 0.445 m**——比直接用量测抖动小得多；
- 4 个椭圆是估计协方差的 3σ 轮廓：**每来一次量测，椭圆被"压"小一截**——这就是"量测进来、不确定性被收回"的可视化；
- 椭圆朝向沿运动方向拉长：速度不确定使**沿航向**的预测误差更大，这是速度状态的物理直觉。

![卡尔曼滤波](./figures/01_卡尔曼滤波.png)

### 思考题

1. 为什么椭圆的"长轴"基本顺着轨迹方向？（答案：$v_x,v_y$ 的不确定性经 $A$ 传播到位置时，沿速度方向的投影最大。）

## 图2 EKF vs UKF：非线性量测（雷达测距测角）

### 代码核心

量测模型是极坐标：$h(x)=(\sqrt{x^2+y^2},\ \arctan2(y,x))$。EKF 用解析雅可比，UKF 用 9 个 sigma 点：

```python
def H_jac(x):                       # EKF：h 的解析雅可比
    r = hypot(x[0], x[1])
    return [[x[0]/r, x[1]/r, 0, 0],
            [-x[1]/r**2, x[0]/r**2, 0, 0]]
def _sigma(x, P, lam):              # UKF：矩阵平方根（特征分解）
    evals, evecs = np.linalg.eigh(P)
    S = evecs @ np.diag(sqrt((n+lam)*clip(evals,0,None))) @ evecs.T
    pts = [x] + [x+S[:,i] for i in range(n)] + [x-S[:,i] for i in range(n)]
# 更新：K = Pxz @ inv(Szz)，与 KF 完全同构
```

真实轨迹做成**分段速度**：前 30 步直线、中间 30 步转弯（滤波器模型未预知的机动）、后 30 步上坡——**故意让模型与真值打架**，才是真实工程场景。

### 现象解释

- 绿点 = 雷达原始量测（距离+方位），在远处明显"弧状散开"——极坐标噪声在笛卡尔系下非高斯；
- 两条估计轨迹都能跟住转弯，但局部有差别：**EKF 位置 RMSE 0.420 m vs UKF 0.405 m**——非线性强度中等时差距不大；
- 真正看差距的地方：转弯段（最非线性处）EKF 的误差峰明显更高。**把角度噪声从 2° 加到 10° 再跑，差距会翻倍以上——这是"UKF 三阶精度"的实证。**

![EKF与UKF对比](./figures/02_EKF与UKF对比.png)

### 思考题

2. 为什么说 UKF"不用求导"却"精度更高"？（答案：sigma 点直接"穿越"非线性函数，用输出统计量近似分布，保留到三阶泰勒项；EKF 只在一点贴一阶切线。）

## 图3 2D 激光占用栅格 SLAM 最小 demo

### 代码核心

机器人绕 2.4m 半径的圆边走边扫 120 根激光；每根射线**求交环境线段得命中点**，再用 Bresenham 从传感器画到命中点：

```python
FREE, OCC, UNK = 0.0, 1.0, -1.0
grid = np.full((SIZE, SIZE), UNK)
for (px, py, th) in robot_poses:
    for i in range(120):
        d = [cos(th+phi), sin(th+phi)]
        t = min(t, seg_ray_intersect(robot, d, wall_a, wall_b))   # 射线求交
        hit = robot + d * t
        for (gx, gy) in bresenham(cell(robot), cell(hit)):         # 路径=空闲
            grid[gy, gx] = FREE
        grid[cell(hit)] = OCC                                       # 命中=占据
```

### 现象解释

- 墙和障碍被"涂"成**黑色实心**（每帧命中点叠加），房间内部**白色**（射线穿过），未探索区域**灰色**（从未被扫到）；
- 地图锐度来自多帧叠加：单帧激光有噪声，但同一面墙被 80 个位姿、每姿 120 根射线反复命中——**log-odds 加法的时间平均把噪声滤掉了**；
- 注意机器人轨迹（红线）穿过的区域全白——**自由空间证据与占据证据按贝叶斯累加，先验 0.5 的格子一旦被穿过，几乎不会再被误判为障碍。**

![占用栅格SLAM](./figures/03_占用栅格SLAM.png)

### 思考题

3. 如果机器人只站在一个位置不动，扫描 1 小时，地图会发生什么？（答案：只更新可视线索所在方向的格子，其余保持未知——**"没扫到 ≠ 空地"**，这正是占据概率初始化为 0.5 的意义。）

## 图4 位姿图 SLAM：手写高斯-牛顿图优化（本章最硬核）

### 代码核心

真值是一条 **8×4m 的闭合矩形**（机器人回到起点）。里程计每步叠加 **1° 航向偏置**（陀螺零偏），63 步累计约 63°——终点被"算"到了 8.6m 外：

```python
# 里程计边：相对位姿 + 每步 1° 航向偏置 + 噪声
z = rel_pose(gt[i], gt[i+1])
z = [z[0], z[1], z[2] + deg2rad(1.0)] + noise
# 回环边：终点 ≈ 起点（真值闭合 → 量测 ≈ [0,0,0]）
loop = rel_pose(gt[0], gt[-1]) + small_noise
```

SE(2) 残差（搬回 $x_i$ 局部系）与解析雅可比（对照 Grisetti 教程）：

```python
def err_pose(i, j, z, X):                 # e = z^{-1} ⊕ (X_i^{-1} ⊕ X_j)
    d = rot2d(z[2]).T @ (rot2d(X[i][2]).T @ (X[j][:2]-X[i][:2]) - z[:2])
    return [d[0], d[1], wrap_angle(X[j][2]-X[i][2]-z[2])]
def J_i_jac(...):                          # ∂e/∂X_i（解析，3×3）
def J_j_jac(...):                          # ∂e/∂X_j（解析，3×3）
# 高斯-牛顿：H Δx = -b，每轮重线性化
H = Σ JᵀΩJ;  b = Σ JᵀΩe;  Δx = solve(H, -b);  X += Δx
```

### 现象解释

- **红线（纯里程计）**：带航向偏置的轨迹严重弯曲，终点（红*）离起点 **8.57 m**——这就是"漂移"的真实观感；
- **蓝线（图优化后）**：一个回环约束，把整条 64 节点链"拧"回矩形——**位置 RMSE 4.883 m → 0.097 m（50.3 倍），航向误差 35.29°→0.67°，缺口 8.57m→0.03m**；
- **右图收敛曲线**：$\chi^2$ 从 227221 单调降到 669（约 2.5 个数量级），3~4 轮迭代即收敛——高斯-牛顿在"好初始值"下收敛极快；
- **残差停在 669 不为 0**：这是**未建模航向偏置**的代价——优化器同时满足"带偏的里程计"与"回环闭合"的最佳平衡点。**把它建模进状态（状态增广）是继续压 $\chi^2$ 的研究方向——答案见图6。**

![位姿图优化](./figures/04_位姿图优化.png)

### 数值自检（论文级习惯）

- 解析雅可比 vs 中心有限差分：**误差 $1.3\times10^{-10}$**——雅可比写没写对，用数值差分一验便知；
- 图优化前后对比在**同一参考系**（里程计系：原点=节点0）——坐标系不一致的 RMSE 对比毫无意义，这是初学者最容易犯的错误。

### 思考题

4. 把回环边权重调大 100 倍，优化结果会怎样？调小 100 倍呢？（答案：权重大→轨迹被"焊死"在闭合（但里程计细节被压扁，矩形略失真）；权重小→回环几乎不生效，结果≈纯里程计。**信息矩阵就是每条边的"发言权"。**）

## 图5 SLAM 管线全景（架构图）

### 内容

```
传感器层(LiDAR/相机/IMU/编码器) ——> 前端 Frontend(扫描匹配/里程计)
        ——> 回环检测 Loop Closure ——> 后端 Backend(图优化/因子图/卡尔曼)
        ——> 建图 Mapping(占用栅格/点云) ——> 输出(位姿轨迹 + 地图)
```

### 这张图怎么读

- **三种信息流**：传感器流（实时逐帧）、约束流（相对位姿+回环）、优化流（全局修正）；
- **前端是"局部"的**（逐帧匹配，快但会漂），**后端是"全局"的**（图优化，慢但准），**回环是"粘合剂"**（把两段时间上"同一地点"的节点连起来）；
- 定位与建图互相依赖、交替进行——**本章图1~图4 分别是这条管线的"零件"，图5 是整机**。

![SLAM管线全景](./figures/05_SLAM管线全景.png)

### 思考题

5. 为什么"传感器→前端→后端→建图"要分层，不能一步到位？（答案：一步到位 = 全状态 EKF-SLAM，状态维数随地图爆炸；分层让前端只管逐帧、后端只管全局、建图只管表示，每层都能单独优化替换——这就是 LIO-SAM 等框架"模块化"的原因。）

## 图6 状态增广 / 在线标定（本章科研顶点）

### 代码核心

图4 的 $\chi^2$ 停在 669 压不下去——**不是优化器不行，是模型缺了"偏置"这一项**。修复办法：给优化变量加一个全局标量 $\delta$（每步航向偏置），里程计边量测改成 $z_{\text{eff}}=z-[0,0,\delta]$：

```python
def optimize_aug(init):                       # 未知量 = 3N 位姿 + 1 偏置
    delta = 0.0                               # 偏置初值（未知）
    for it in range(iters):
        for (kind, i, j, z, info) in edges:
            if kind == "odom":
                z_eff = [z[0], z[1], z[2] - delta]      # 扣除估计偏置
                e = err_pose(i, j, z_eff, X)
                Jd = jac_delta(...)                     # ∂e/∂δ = -∂e/∂z_θ
                # H Δx = -b 中，δ 多一行一列（与位姿块一起拼装）
            else:                                       # 回环边无偏置
                e = err_pose(i, j, z, X)                # Jd = 0
        delta += dx[-1]                                 # 更新偏置估计
```

对 $\delta$ 的雅可比（链式法则：$z_{\text{eff}}[2]=z_2-\delta$）：

$$
J_d=\frac{\partial e}{\partial\delta}=-\frac{\partial e}{\partial z_{\text{eff}}[2]}
=\begin{bmatrix}
-\frac{dR_z^T}{d\theta}\big(R_i^T\Delta p-z_p\big)\\ +1
\end{bmatrix}
$$

### 现象解释

- **左图 χ² 收敛对比**：普通图优化（蓝）停在 669 压不下去；**状态增广（红）继续塌到 0.47**——接近量测噪声水平（自由度≈190），说明模型"诚实"了；
- **右图偏置估计**：$\hat\delta$ 从 0 迭代收敛到 **0.985°**（真值 1.0°）——**只靠 63 条里程计边 + 1 条回环边，就把传感器系统误差无偏地标定出来**，这就是 VINS/ORB-SLAM3 里 IMU 偏置在线标定的最小复现；
- **轨迹 RMSE 反而 0.097 → 0.143 m**：普通优化把偏置"憋"进位姿（过拟合，残差大但表面更贴真值）；增广把偏置正确地分离给 $\delta$——**残差小 ≠ 轨迹准，报精度必须报模型假设**。

![状态增广在线标定](./figures/06_状态增广在线标定.png)

### 数值自检（论文级习惯）

- $\partial e/\partial\delta$ 解析 vs 中心有限差分：**误差 $8.2\times10^{-11}$**；
- 可观测性验证：删掉回环边再跑 `optimize_aug`，$\hat\delta$ 无法收敛（整体旋转 + 偏置互相抵消）——**回环是偏置可辨识的前提**，自己动手验证这条。

### 思考题

6. 为什么"只有里程计边时 $\delta$ 不可观，加上回环边就可观"？（答案：纯里程计边全是相对约束，整体旋转 + $\delta$ 的组合不改变任何残差，$\delta$ 被"吸收"进整体旋转；回环边把起点和终点"焊接"起来，偏置的累积效应（63 步 × δ）变成可测的闭合误差——δ 从此唯一确定。）

## 本章仿真要回答的三个核心问题

1. **"最优估计"到底在算什么？** —— 贝叶斯后验：预测（积分）与更新（相乘），KF 是它在"线性+高斯"下的精确解（图1），EKF/UKF 是它在非线性下的两种近似（图2）；
2. **地图怎么建？** —— 占用栅格 + log-odds 贝叶斯加法（图3），射线投射 + Bresenham 完成"量测→格子"的映射；
3. **漂移怎么修？** —— 位姿图 + 高斯-牛顿：把整条轨迹当变量，让所有约束残差最小（图4），回环检测提供全局一致性（图5）。**一个回环，50 倍精度提升——这就是 SLAM 后端存在的意义。**
4. **模型错了怎么办？（科研）** —— 残差压不下去 = 模型缺项：把缺的参数（偏置 $\delta$）增广进状态联合估计（图6），$\chi^2$ 塌到噪声水平、系统误差被无偏标定。**这是从"会调参"到"会建模"的分水岭。**

> 下一步：把本章手写图优化换成 g2o/GTSAM（现代因子图库），数据格式 `.g2o` 有 10 行内规格；再进一步，把图3 的"已知位姿建图"升级成"边建图边优化"——你就从"看懂 SLAM"走到了"会写 SLAM"；把图6 的单个偏置推广到"偏置 + 尺度 + 外参"联合标定，就是 LIO-SAM 级别的研究入口。
